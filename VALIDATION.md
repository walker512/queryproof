# Validation scope

## Identified code baseline

This documentation candidate is based on public commit
`4ddcab79ccc2257f11bc7d1aa6ccc38e0eceb655`. Its downloaded source ZIP comment identifies
that commit; all 33 non-workflow files matched the independently reviewed
strict-display RC2 candidate. Workflow contents were not inspected. This update
changes documentation only and must not be described as a new runtime test run.

## Evidence applicable to that baseline

- Independent Linux execution of **130 tests, zero skips** covered the complete
  suite. Real subprocess CLI cases included rechecksummed/re-rendered boolean,
  integer, real and signed-zero substitutions, nested diagnostics, hostile HTML
  changes, unknown versions, layouts, limits and default-mode compatibility.
- Public [run 44274499101](https://github.com/walker512/queryproof/actions/runs/44274499101)
  for that exact commit was observed as **Success**, with **four jobs completed**.
  The verification read the run overview, not individual job logs. It does not
  establish every runner detail, a later HEAD state or a new browser review.
- Strict display verifies exact generated bytes without opening HTML. No new
  browser, accessibility or human usability acceptance is claimed for it.
- Matching receipt/tool and SQLite version/source/build remains necessary. Neither
  local tests nor the hosted summary guarantees all operating systems, SQLite
  builds, hostile databases or concurrently modified files will work safely.

## Interpret results narrowly

Recomputation is not semantic correctness, source truth or proof of authorship.
Checksums are not signatures. Strict display is not an arbitrary HTML sanitizer.
Publication is private/exclusive at creation, not a multi-file transaction or a
power-loss guarantee. Windows ACL isolation has not been established.

Older installation, browser, platform and comparison results are retained in
[CHANGELOG.md](CHANGELOG.md), with their original version scope. Historical
“candidate/unpublished” labels there describe the time of the original record.
They are not the status of the identified public baseline above. Details in older
feature guides similarly describe the execution performed for that increment.
